Contrôle Radar Phase 3

Pour chaque offre : ouvre le lien, compare avec « Attendu », puis clique Bon ou Pas bon. Les montants sont annuels bruts, temps plein, en euros (CHF × 1,07). Quand il n'y a pas de fourchette, min = max.

Ce qui a été fait

  • Collecte quotidienne de trois sources : EURES (Luxembourg), Job-Room (Suisse, secondaire) et ADEM (Luxembourg, via Firecrawl car l'API est bloquée depuis GitHub).
  • Chaque offre est stockée brute sur R2, une ligne par offre. Un contrôle hebdomadaire, une compaction mensuelle et une alerte par issue GitHub en cas d'échec sont en place.
  • Le salaire est lu dans le texte de l'annonce : aucune des trois sources n'a de champ salaire. Le cas 1 est donc sans objet.
  • Bugs corrigés après ta relecture : l'annuel n'était pas converti en euros (6 094 au lieu de 79 222), « chèque-repas / jour » était pris pour un salaire, « 2 jours par semaine » forçait un salaire journalier.
  • Chaque salaire a maintenant un minimum et un maximum annuels. Sans fourchette, le maximum est égal au minimum.

Ce qui reste

  • Le retrait d'une offre n'est pas détecté : le cas 5 n'est vérifiable qu'à moitié (salaire vide).
  • Aucune vraie mission freelance (cas 4) n'a été trouvée dans les offres collectées. Aucun salaire non plus chez ADEM (cas 2 et 3).
  • Les liens EURES et Job-Room sont construits à partir de l'identifiant de l'offre. Si l'un s'ouvre sur une page vide, dis-le-moi.
